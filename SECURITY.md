# Security Policy

## Supported Versions

Security fixes are provided for the currently supported release line:

| Version | Supported |
| --- | --- |
| 0.1.x (current release line) | Yes |
| older pre-releases | No |

## Reporting a Vulnerability

Do not report security vulnerabilities in public issues.

Preferred process:
1. Use GitHub Security Advisories (private vulnerability report) for this repository.
2. If repository security advisories are unavailable, contact maintainers privately through
   repository owner channels and mark the message as "Security Vulnerability Report".

## What to Include

Please include:
- Vulnerability type
- Affected file(s)/function(s)
- Reproduction steps
- Proof of concept if available
- Impact assessment
- Suggested remediation if available

## Response Targets

- Initial acknowledgment: within 7 days
- Triage/update: within 14 days
- Fix timeline: depends on severity and reproducibility

## Disclosure

After a fix is available, coordinated disclosure is preferred. We may publish a short advisory in
release notes or the changelog.
